# 2026-09-20 Audio2Face Unity 移植排查（对照 Audio2Face-3D-SDK / -Samples）

## 已逐项核对并确认「与 SDK 一致」的部分（不要再动）

对齐依据：`Audio2Face-3D-SDK/audio2face-sdk/` C++ 源码 + `Audio2Face-3D-Samples/configs/mark_diffusion_stylization_config.yaml`。

### 窗口 / 时序（executor_diffusion_core.cpp GetProgressParameters）
- `nbFramesPerInference = 15 + 15 + 30 = 60`
- `windowSize = bufferLength = 16000`
- `targetOffset = 16000 * 15 / 60 = 4000`（= 0.25 s）
- `startOffset = -paddingLeft = -16000`
- `stride = 16000 * 30 / 60 = 8000`
- 窗口 k：`start = 8000k - 16000`，`end = 8000k`；k=0/1 是 padding 预热窗口（不输出帧），
  第一个正式输出帧（f=15）对应音频 **样本 4000**，不是 0。
- `FrameRate = 60 * 16000 / 16000 = 60fps`

### per-frame 维度（network_info.json）
`skin_size 72006 + tongue_size 16806 + jaw_size 15 + eyes_size 4 = 88831` ✓

### 后处理顺序（关键）
`executor_diffusion.cpp` → inference → **AnimatorSkin.Animate** → resultBuffers.skinGeometry
→ `executor_blendshapesolve.cpp` → `skinSolver->SolveAsync(results.skinGeometry, ...)`
即 **animator 先于 solver**，Unity 的 `SolveSkinAt` 顺序正确。
（prediction 是 delta；animator Step2 加回 neutral 变绝对坐标；solver `TargetIsDelta=false` 再减 neutral。）

### AnimatorSkin 内核（animator_cuda.cu）与 Unity `Audio2FaceSkinAnimator` 逐行一致
- Step1: `skinStrength*delta + eyeCloseDelta*(-eyelidOpenOffset + blinkOffset*blinkStrength) + lipOpenDelta*lipOpenOffset`
- Interpolator degree=2：`alpha = 1 - 0.5^(dt/smoothing)`，三层首尾递推
- Step2: `neutral + smoothedUpper*upperStrength*(1-mask) + smoothedLower*lowerStrength*mask`
- faceMask: `sigmoid((level - (y-minY)/(maxY-minY)) / softness)`

### 官方 Mark 参数（model_config_Mark.json + stylization yaml）已全部正确接入
`lower_face_strength=1.4 / upper=1.0 / skin_strength=1.1 / input_strength=1.3 /
lip_close_offset=-0.03 / eyelid_offset=0.06 / face_mask_level=0.6 / softness=0.0085 /
lower_face_smoothing=0.0023 / upper_face_smoothing=0.001 / tongue_strength=1.3`
`weight_multipliers` 全 1.0、`weight_offsets` 全 0.0（上一轮已清掉硬编码错误 multiplier）。
注意 `alpha≈0.993` → smoothing 几乎不起作用，别指望它平滑抖动。

### 求解器（BlendshapeSolver）
AMat 正则系数、b 的 temporal 项、BVLS、cancelPairs、`_prevWeights` 跨帧传递均与 SDK 一致。
`Reset()` 只清 `_prevWeights`，**不清 `WeightBaseline`** —— 所以可以安全地在换音频时 Reset。

## 本轮（第二轮）修复：眨眼

### 根因（重要结论，写死）
**Audio2Face-3D SDK 不带眨眼生成器。** `blinkOffset` 是**应用层每帧**喂给
`AnimatorSkin` 的参数（`animator.h: SetBlinkOffset`，默认 0、取值 [0,1]；
`animator.cpp` 只做 `SetBlinkOffset(params.blinkOffset)` 透传）。
Step1 里它走 `eyeCloseDelta * (-eyelidOpenOffset + blinkOffset * blinkStrength)`。
不喂就只剩 `-0.06` 的静态睁眼偏置 → **眼睛一次都不眨**。
日志铁证：`[A2F逐帧]` 里 eyeBlinkL/R 全程 ≤0.022。
（SDK 里只有 blinkStrength/eyelidOpenOffset/blinkOffset 三个参数，没有随机调度器。）

### 改动
- 新增 `Assets/Scripts/Audio2Face/A2FBlinkGenerator.cs`：随机眨眼调度器
  - 按**帧的音频时间戳**排期（不是墙钟）：推理是提前算的，用墙钟会错位
  - 间隔 2.5~6 s、时长 0.16 s、闭眼占 40%（睁眼比闭眼慢）、15% 连眨两次
  - smoothstep 包络；`Evaluate(t)` 要求 t 单调不减
- `Audio2FaceSkinAnimator.SetBlinkOffset(float)`（对齐 SDK 命名）
- `Audio2FaceDiffusionPipeline.SolveCenterFrames`：
  `winStart = _windowEnd - BufferLength`，帧 f ↔ 样本 `winStart + f*(BufferLength/FramesPerInference)`，
  每帧求值后 `SetBlinkOffset`
- 标定路径 `CalibrateRestPose()` / `Reset()` 强制 `SetBlinkOffset(0)`（否则静息基线混入闭眼量）
- `Audio2FaceDiffusionConfig` 新增 `enableBlink / blinkIntervalMin/Max / blinkDuration / blinkDoubleChance / blinkSeed`
- 新增 `[A2F眨眼]` 日志（不能放进 `[A2F逐帧]` 的 sb 块：trace 只覆盖前 2 s，眨眼最早 2.5 s）

### 张嘴幅度的旋钮
官方 `input_strength=1.3 × lower_face_strength=1.4 × skin_strength=1.1 ≈ 2 倍`，
是为 MetaHuman 调的。非 MetaHuman 目标（Sloth_Head2）jawOpen 会到 0.7+。
新增 `Audio2FaceDiffusionConfig.overrideInputStrength + inputStrength`（默认关闭，保持官方值），
配合已有的 `overrideSkinAnimator` 可把三层增益都压到 1.0。
`inputStrength` 语义已核对：`audio_accumulator.cpp` 对音频窗口整体相乘，Unity 在 `Model.Run` 里一致。

### 本次日志确认「无问题」的点
- 帧-音频映射正确（窗口右端 16000→24000→…，30 帧/次，边界基本连续）
- `predRMS=3.9040` 恒定**不是 bug**：输出是 delta(RMS 6.1) 叠在 neutral(RMS 88.9) 上，静态主导
- warmup 判据 `_windowEnd < BufferLength` 正确（Unity 从 k=1 起，只需丢弃 1 个 padding 窗口）
- 音频增益链路、`FramesPerInference/SampleRate` 等属性名均已核对

## 第三轮（用户反馈「口型还是怪异、和音频不匹配」）

### 时序结论：对齐是**对的**，不要再动偏移量
推演（已用日志验证）：队列第 k 帧 = 全局帧 15+k，自带音频时刻 =(15+k)/60；
播放判据 `(T-0.25)*60` 使它在 T=(15+k)/60 显示 → **零偏移**。
`_targetOffsetSec` 的 0.25s 只是补偿「前 15 帧不存在」，不是把动画延后 0.25s。

### 本轮日志读出的三个真问题
1. **幅度饱和（「怪异」的主因）**：`jawOpen` 峰值 0.70~0.73；`mouthClose` 连续 13 帧顶在
   **1.000（BVLS 上界）**；且 jawOpen 与 mouthClose 同时非零（t=1.60s: jaw 0.126 / close 1.000）
   互相打架。权重 |w| 合计 2.2~6.3。→ lower_face_strength=1.4 对 Sloth_Head2 过头。
2. **眨眼第一次出现在 t=7.60s**：`A2FBlinkGenerator.Reset()` 里 `_scheduledUpTo = minInterval`，
   第一次眨眼 = `minInterval + NextInterval()` ∈ [5.0, 8.5]s。已改为 `_scheduledUpTo = 0`。
3. **开头僵脸**：开播那一刻队列为空，第一批 30 帧要 ~350ms 才出来，期间脸不动，
   然后 Update 一次补 6~20 帧 → 观感「慢半拍」。已加预缓冲。

### 本轮改动
- `A2FBlinkGenerator.Reset()`：`_scheduledUpTo = 0`
- `Audio2FaceDiffusionConfig` 新增「幅度」段：`overrideFaceStrength`(默认 true) /
  `lowerFaceStrength=0.8 / upperFaceStrength=1.0 / skinStrength=1.0`——只覆盖三个增益，
  其余（lipOpenOffset/eyelidOffset/平滑/mask）仍用官方值；必须在**求解前**压低，
  事后整体乘系数救不了已饱和截断到 1.0 的通道
- `Audio2FaceDiffusionConfig` 新增 `prebufferFrames = 60`（麦克风实时场景改为 0）
- `Audio2FaceDiffusionPipeline` 构造函数：应用 overrideFaceStrength；日志打印参数来源
- `Audio2FaceDiffusionComponent.Update`：丢帧追赶只按**真正取到**的帧推进 `_displayedFrames`
  （原写法在队列不够时仍加满 drop，会造成不可恢复的永久滞后）
- `ProcessClipRoutine`：预热后新增「阶段 2.5 预缓冲」，攒够 prebufferFrames 帧才开播
- 新增 `[A2F同步]` 日志：每 30 帧打印 `音频时刻 vs 动画帧时刻` 的毫秒差 + 队列深度，
  正=动画超前、负=滞后。下一轮先看这条判断是否还有系统性偏移

## 第四轮：预缓冲引入的回归（我自己写的，已修）+ 幅度已验证

### 回归（重要，别再犯）
第一版预缓冲 `while (PendingFrames < prebuffer)` 每帧 Update 都推 4096 样本，
推理一次要 350~600ms → 攒够 60 帧时**音频已推到 102016/128820（6.4s）**。
更糟的是：`Update` 里「无音频时钟」的累加器分支在 `_audioPlaying=false` 期间
**以 60fps 白消费帧**（脸在没声音时先动了一遍）。开播时队列头已对应 2.7s 后的音频
→ **动画整体超前 2.7 秒**。

修法两条，缺一不可：
1. 新增 `_holdFrames`：`ProcessClipRoutine` 开头置 true、开播前置 false；
   `Update` 累加器分支开头 `if (_holdFrames) return;`
2. 预缓冲先算推送上限 `pushTarget = warmupSamples + ceil(prebuffer * samplesPerFrame)`
   （samplesPerFrame = BufferLength/FramesPerInference = 266.67），推够就只等推理；
   等推理不用 `IsBusy`（_runRequested 置位与 _busy 置位之间有窗口期会误判），
   改用「无进展计数 > 180 帧（~3s）」退出

### 「下巴动、嘴不开」的数学根因（写得死一点）

## 第十二轮：「扫掠 jawOpen 嘴能张开，播放并驱动嘴完全不动」

### 诊断逻辑（写死）
手动扫掠走 `Tester.ApplyManual→Target`，实时驱动走 `OnDriverFrame→Target`，**写同一网格**。
扫掠动 → 网格/jawOpen 形状没问题（[A2F自检] 也证明 jawOpen(1.0) 净开口 3.14%）。
故「实时完全不动」只可能是：(A) `OnFrameApplied/OnDriverFrame` 根本没跑（帧消费被门控）、
或 (B) frame 权重≈0。**不是网格问题**。
复核排除：`BlendshapeSolver.Reset()` 只清 `_prevWeights`，**不清 `WeightBaseline`** →
`ProcessClipRoutine` 的 `_pipeline.Reset()` 不会冲掉静息基线（排除「权重被清零」）。

### 本轮修复
1. **`PlayClipAndDrive` 双音频回归（前几轮我自己引入的）**：Tester 自己 `_audio.Play(Clip)` +
   `ProcessClipRoutine` 预热完又 `_audioSource.time=0; Play()` 重播。若同一 AudioSource → 声音跳回开头、
   动画时钟被重置；若两个 → 双声 + 嘴对不上音。两种都让「播放并驱动」看着像嘴不动。
   → 现在声音统一交给 Driver（`PlayAudioWhileProcessing`），只在 Driver 不出声时 Tester 才兜底自播。
2. **`ProcessClipRoutine` 预热等待加 8s 超时**：原来 `while(ConsumedSamples<warmupSamples) yield`
   无限等 → 一旦推理没跑起来就永久卡住，`_holdFrames` 恒 true + `_audioPlaying` 恒 false，
   Update 两条消费路径全堵 → **嘴彻底冻结**。加超时 + 报警。
3. **Start 时 `RealtimePlayback=false` 明确报警**：它是「消费帧队列」总闸（Update 里 `if(!RealtimePlayback)return`），
   关着 → `ApplyFrame` 从不跑 → 嘴静止但扫掠仍动，正是本症状头号嫌疑。

### 新增定位诊断（都**不看 debugMode**，三条对照唯一定位）
